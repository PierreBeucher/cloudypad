## Release

### Before release testing

Some tests are required before release:

- [ ] `task test-unit` (done by CI)
- [ ] `task test-integ-full-lifecycle-all` (done manually since it requires real Cloud accounts)
- [ ] `task test-integ-scaleway-lifecycle-with-server-deletion` (done manually since it requires real Cloud accounts)

### Do release

GitHub authentication uses your local `gh` login (`gh auth login`, needs repo contents + pull requests write). Alternatively, `gh` also reads `GITHUB_TOKEN`/`GH_TOKEN` env vars if set (eg. via `source <(novops load -e release)`).

```sh
# Create release with version computed by git-cliff from commits since previous release
# (or resume the release in progress)
task release-create

# Or with explicit version
task release-create -- 0.46.0

# Dry run: stamp and commit on local release branch only, nothing pushed
CLOUDYPAD_RELEASE_DRY_RUN=true task release-create
```

Release is fully automated, no prompt. It ends by printing a PR `release-X.Y.Z` → `master`.

**Final manual action: review and merge the PR with a merge commit** (no squash, no rebase) - tag `vX.Y.Z` must stay reachable from `master` for next release notes generation. Merging makes the release live: users install from `master/install.sh` which pins the released version.

### Release process

All work happens on branch `release-X.Y.Z`, the script never writes to `master`:

1. Create (or reuse) branch `release-X.Y.Z` from `master` and commit `chore(release): vX.Y.Z`:
   - Version stamped in `package.json`, `cloudypad.sh`, `install.sh` and `flake.nix` (with `cloudypad.sh` hash)
   - `CHANGELOG.md` section generated by [git-cliff](https://git-cliff.org) (config: `cliff.toml`) from `feat`, `fix` and `perf` commits since previous release. Other commits are ignored.
2. Tag `vX.Y.Z`, triggering the `Release` workflow which builds and pushes container images
3. Wait for `Release` workflow success
4. Verify published images (multi-arch core image, Sunshine image, core image version) and that `flake.nix` hash matches `cloudypad.sh` served for the tag
5. Publish GitHub release (marked latest) with `CHANGELOG.md` section as notes
6. Open PR `release-X.Y.Z` → `master`. Not merged by the script.

CI test jobs are skipped on `release-*` PRs: tests already ran on `master` and images are built by the `Release` workflow.

Version resolution when no version is given: release in progress (open release PR or remote release branch) if any, otherwise `git cliff --bumped-version` (`feat` bumps minor, other changes bump patch).

### Resume, retry and abort

The script is idempotent: re-running it resumes from current remote state (branch, tag, CI run, GitHub release, PR) and skips completed steps.

- `Release` workflow failed: rerun failed jobs with `gh run rerun <run-id> --failed` (command printed by the script) and re-run `task release-create`
- Unrecoverable problem (eg. code fix needed): abort, fix on `master`, release again

```sh
# Close PR, delete GitHub release, tag and release branch.
# Refused if release PR is already merged: fix forward with a new release.
task release-create -- --abort 0.46.0
```

## Maintenance

## Regular updates

First:
- [ ] Nix flake update `nix flake update`
- [ ] Also bump version to latest stable if possible

Then:
- [ ] Node dependencies `pnpm update`
- [ ] NVIDIA Display driver version 
  - Take latest Display Production Linux x86_64 version at [NVIDIA Unix Driver archive page](https://www.nvidia.com/en-us/drivers/unix/)
  - Update in `ansible/roles/nvidia-driver/defaults/main.yml` `nvidia_driver_display_dotrun_install_version`
- [ ] NVIDIA Datacenter driver version 
  - Take latest Datacenter Linux x86_64 version at [NVIDIA Unix Driver archive page](https://developer.nvidia.com/datacenter-driver-archive)
  - Update in `ansible/roles/nvidia-driver/defaults/main.yml` `nvidia_driver_datacenter_dotrun_install_version`
- [ ] NVIDIA Container Toolkit version
  - Check available versions on [APT package](https://nvidia.github.io/libnvidia-container/stable/deb/amd64/Packages)
  - Update in `ansible/roles/nvidia-driver/defaults/main.yml` `nvidia_container_toolkit_version`
- [ ] Wolf version and config
  - [ ] Run `hack/update-wolf-images.sh` to update default images in Ansible role
  - [ ] Update Wolf config template in `ansible/roles/wolf/templates/wolf-config.toml` using default config
    - Generate default config by running a Wolf container (will generate default config on start) and copy it:
    ```
    docker pull ghcr.io/games-on-whales/wolf:stable

    # Run Wolf in the background to auto-generate config file on startup
    docker run -d --name wolf-config ghcr.io/games-on-whales/wolf:stable

    # Copy config file
    docker cp wolf-config:/etc/wolf/cfg/config.toml .
    ```
    - Ensure proper Ansible templates variables are used in TOML config:
      ```toml
      hostname = "{{ wolf_instance_name }}"
      uuid = "{{ wolf_instance_name | ansible.builtin.to_uuid }}"
      # ...

      # For each app, use the related Ansible image, eg for Firefox:
      [apps.runner]
      type = "docker"
      name = "WolfFirefox"
      image = '{{ wolf_app_firefox_image }}'
      ```
- [ ] Sunshine Dockerfile `containers/sunshine/Dockerfile`
  - [ ] Base image version `FROM` - See available tags from [Docker Hub](https://hub.docker.com/_/ubuntu). Make sure to use the imaghe SHA for reproducibility.
  - [ ] Steam version `CLOUDYPAD_STEAM_VERSION` - see stable version at [Steam archive](https://repo.steampowered.com/steam/archive/stable)
  - [ ] Update `SUNSHINE_VERSION` with [latest Sunshine release](https://github.com/LizardByte/Sunshine/releases)
    - Prefer the Latest release
    - Do NOT use Release Candidate or Pre-release, make sure to use actual release. Pre-release and RC may be removed from GitHub later, we need a release that will be kept available to ensure reproducibility of our build.
  - [ ] Update `LUTRIS_VERSION` with [latest Lutris release](https://github.com/lutris/lutris/releases)
  - [ ] Update `HEROIC_VERSION` with [latest Heroic Games Launcher version](https://github.com/Heroic-Games-Launcher/HeroicGamesLauncher/releases)
  - [ ] Update `CLOUDYPAD_HEROIC_DEFAULT_GEPROTON_VERSION` with [latest GE-Proton version](https://github.com/GloriousEggroll/proton-ge-custom/releases)
- [ ] CLI Dockerfile (`Dockerfile` at root)
  - [ ] Pulumi version - see [Pulumi release](https://github.com/pulumi/pulumi/releases)
  - [ ] Node version - see [Docker Hub](https://hub.docker.com/_/node)
  - [ ] Ansible version installed by pip - See [Ansible PyPI page](https://pypi.org/project/ansible/)
